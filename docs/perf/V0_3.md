# v0.3 性能验收（§16.5 实测记录）

判据是「记录，不设人为阈值」——除非本文件某行明确写了「新增阈值」。
每行都带测量日期与构建形态；换机器/换构建后数字会变，机理不变。

## P2 — 裁决开销（E25 / #331）

`process_intent` 四关卡（合法/风控/预扣探针/生存绑定）的延迟，纯函数 +
`Ledger` 探针（reserve→release，净零）。测量：`cargo test -p blitzkrieg-core
--lib arbitration_latency -- --nocapture`（macOS arm64，10_000 次干净入场建议，
含 `OrderIntent::validate` + `RiskGate::check_with_equity` + 一次探针预扣 +
`effective_stop_pct` 投影）。

| 构建 | p50 | p99 | max | 日期 |
|:--|:--|:--|:--|:--|
| debug | 2 µs | 3 µs | 45 µs | 2026-09-26 |
| release | <1 µs | <1 µs | 5 µs | 2026-09-26 |

对照：引擎 tick 周期 50 ms（§16.5 P3 的 10× 余量原则）。裁决开销比 tick 小四
个数量级；每建议两条字符串格式化是主要成本，已经是纯分配、无系统调用。

## P1 — 经济结论不变（E25）

`exit-economics-check.mjs` 开审计与 `--arm --no-intent-audit` 两种情形都必须
通过既有 `BASELINE`（`75fd8140`，不重录）。结果见 PR #341 的验收输出。

## P1 — 出厂字节同财经（E26 / §4.1）

系统性限额的出厂承诺有一个性能面：**未武装 = 零开销**。`any_armed()` 在管线
入口短路——九个限额全 0 时，Gate 2 不做任何系统判定、不推任何 trace，审计
输出与未加风控的管线逐位一致。旁证：`risk-systemic-check.mjs` 的「factory
pipeline: no systemic trace」check（真核 + 真策略，扫 gate traces 无 systemic
字样）；E25 的 `exit-economics-check.mjs` BASELINE 与 `intent-audit-check.mjs`
在 E26 改动后必须继续绿（P1 字节门禁本身就是回归测试）。

武装态的增量是一次 `judge_entry` 纯函数（同一量级于 Gate 2 既有的
`check_with_equity`，µs 级）+ Gate 4 换传显式梯子参数（同一次投影计算）——
对 50 ms tick 的余量原则（§16.5 P3）没有可测影响，不设新阈值。

## P3 — Lua 回调延迟（E30 / §16.5，0.3 唯一新增阈值）

沙箱每回调延迟。测量：`cargo test -p blitzkrieg-lua-runtime --lib
callback_latency -- --nocapture`（macOS arm64，5_000 次稳态采样）。两种回调
形态都测：**常规回调**（构建 20 档网格意图表 + 算术——合法策略每轮的典型
形态）与**满预算回调**（~0.95e6 条 VM 指令的紧循环——最坏合法形态，刚好
不触发钩子投毒）。

| 构建 | 形态 | p50 | p99 | max | 日期 |
|:--|:--|:--|:--|:--|:--|
| debug | 常规 | 8 µs | 20 µs | 42 µs | 2026-09-29 |
| debug | 满预算（0.95e6 指令） | 2.24 ms | 2.34 ms | 2.35 ms | 2026-09-29 |
| release | 常规 | 1 µs | 5 µs | 34 µs | 2026-09-29 |
| release | 满预算（0.95e6 指令） | 683 µs | 981 µs | 1.04 ms | 2026-09-29 |

**新增阈值（§16.5 P3）：常规回调 p99 ≤ 5 ms**（相对 50 ms tick 留 10× 余量；
release 口径）。实测 p99 = 5 µs，余量三个数量级。机理上指令预算本身就是延迟
上界：满预算回调 release 档 ~1 ms、debug 档 ~2.3 ms，都远小于一个 tick——
钩子每 10_000 条指令检查一次，超限先投毒再报错，线程立即让出。测试用两条
断言钉住：常规 p99 ≤ 5_000 µs；满预算 max ≤ 50_000 µs（一个 tick）。超线的
处置是**下调指令预算并把新数字记录在此**，不是放宽线。

## P4 — K 线聚合吞吐与内存上界（E29 / §16.5，记录不设阈值）

测量：`cargo test -p blitzkrieg-core --lib ten_k_trade_throughput --
--nocapture`（macOS arm64）。10_000 笔 tick × 9 个出厂 interval
（`with_default_intervals`），时间戳有序（venue 流的到达序）；预热 500 笔后
只对尾段计时——重喂预热段会被快周期 interval 正确判乱序丢弃，计时必须只测
折叠成本，不含丢弃。

| 构建 | 总耗时 | 每 tick | 日期 |
|:--|:--|:--|:--|:--|
| debug | 66 ms | 6.99 µs | 2026-09-29 |
| release | 9 ms | 1.03 µs | 2026-09-29 |

内存上界用 §10.3 公式（`AggregatorStats::memory_bound_bytes`）按现实舰队规模
计：100 symbols × 9 intervals × (1 生长 bar + 1_000 有界闭合历史) ×
sizeof(Kline)=136 B ≈ **116.8 MB**——有界、启动前可预估（cap=1000 是 E29 披露
偏差的常量，不是无界缓存的借口）。吞吐对照：10k tick 是单 symbol 一小时的
量（tick 周期 ~360 ms），每 tick µs 级，对 50 ms 引擎 tick 余量四个数量级。

## Lua 栈体积增量（E30 / E10-d 尺寸纪律）

mlua vendored（Lua 5.4 源码随构建编译，无系统依赖）的两层记录：

- **静态库面（链接前）**：`libmlua` 4.9 MB + `libmlua_sys` 0.5 MB +
  `liblua_src` 0.1 MB rlib（release deps，含未消除的元数据/符号面）。
- **实际链接增量（0.2.1→0.3.0 全量特性集，同机同 profile）**：`blitzkrieg-core`
  12.69 MB（v0.2.1 代码，无 Lua 栈——该树 deps 里零 mlua 产物可证）→
  12.86 MB（0.3.0：mlua vendored + E24–E29 全部新增）= **+0.17 MB ≈ +1.3%**。
  Lua 栈的净贡献**小于**这个全量增量——LTO + 单 codegen unit 消除了静态库
  里未走到的大部分。`binary-size-check` 门禁绿：12.86 MB = 单二进制 50 MB
  预算的 25.7%；体积增量由**既有** E10-d 门禁守住，不设新阈值。
