## 为什么 -$107 不是「策略亏了」

poly simulator 是本地结算的 dry 场：仓位到期时若场地**从未给过裁决**，内核按
`unverifiable_expiry` 以兜底价（最后已知 mid，为 0 则入场价）平仓并入历史——
`source=fallback`。这 218 笔的 0% 胜率是**记账产物**（兜底价 ≤ 入场价即记亏），
不是「策略 218 次看错方向」。#1015 刚交付的双模型正是为这种场景设计的：

- `BK_UNVERIFIED_EXPIRY_POLICY=cash`（当前生产，boot echo 实证）
  → 兜底价即刻记入现金，未核实部分直接成损。
- `BK_UNVERIFIED_EXPIRY_POLICY=receivable`
  → 记入 receivable 池（未核实敞口，不贷现金），reconcile 按场地真值双行校正；
    48h 冻结上限 + 琥珀横幅；day budget/连损断路器基数只算可支用现金。

**这是记账姿态裁决，不是调参**：receivable 让「未核实」保持未核实状态而非提前
判亏，可读性更真（策略本体的 90.9% 不再被 fallback 噪声稀释），但 dry 场没有真值
可校正，48h 后仍会落地——**它改变的是「何时、以什么口径承认这笔损失」，不改变
最终现金**。是否切换由操作员裁决（决定权不在工程侧）。

## 另：账本口径 vs 成交折叠口径差 $2.31

`账本净利 = 现金 − 累计种子 = $29.17`；`成交折叠净利 = $31.48`；Δ=$2.31。
差额来自成交行的**费率模型**（`0.07·p(1−p)`）与账本**现金真值**（#995 后的实际
扣费）不同源。这正是 PR #1023（现金流水=唯一真相）要消灭的：面板钱数改走账本，
成交折叠降级为「成交口径」展示。**不需要额外修**。

## 裁决建议（待操作员）

1. **参数：不动**。本体 WR 90.9% / PF 8.56 已在「恢复到 80% 以上」目标之上；
   调参只会引入回归。up 腿保留（今日为正）。
2. **fallback 记账：二选一**——
   - 切 `receivable`：读到的胜率/净利反映真实策略质量（不被 -$107 噪声污染），
     代价是未核实敞口挂账 + 横幅（现金不提前承认，真值到位后校正）。
   - 保持 `cash`：口径最简（即时现金真值），代价是 dry 场无裁决的事实被记成实亏。
3. 无论选哪个，**「赚的太少」的可测面已收敛**：真钱流动只由本体决定，本体是正的。
